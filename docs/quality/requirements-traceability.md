# Project AMANOR requirements traceability

This matrix maps every public page (`P01`-`P13`) and signature feature (`F01`-`F15`) to current authoritative evidence. It deliberately records partial and blocked work: a green repository gate does not convert an uncovered requirement into a verified one.

Status meanings:

- `VERIFIED`: the implemented scope has direct automated evidence and no known engineering acceptance gap; external content or stakeholder approval may still keep the ledger item in review.
- `PARTIAL`: substantial feature behaviour is directly tested, but named acceptance requirements remain.
- `FOUNDATION`: route, schema, or shared infrastructure exists, but the specialised experience is not implemented.
- `BLOCKED`: the necessary decision, content, consent, owner, or external service is unavailable.

## Shared gates

The root `npm run check` gate covers formatting, dependency boundaries, canonical-copy rules, OpenAPI drift, generated contracts, traceability, observability, security policy, committed-secret signatures, strict type checking, zero-warning lint, unit/component suites, production builds, frontend bundle isolation and the Lite compressed-transfer budget. Mongo transaction/index evidence is separately exercised by `npm run test:integration --workspace @amanor/api` against the replica test service.

The Playwright baseline directly covers the public and Admin/CMS journeys named above, including live NestJS password/TOTP authentication, secure cookie issuance, bearer-protected session retrieval, logout and the implemented Protocol Desk operator/Principal lifecycle against ephemeral MongoDB. Axe automation covers four key public routes and the Admin sign-in boundary across Chromium, Firefox and WebKit; it does not replace manual assistive-technology testing. Lighthouse CI enforces production category, LCP, CLS and route-specific transfer budgets on three representative Lite routes plus the interactive Atlas, including its 2.5-second lab TTI ceiling. The production-asset Lite gate separately covers all 18 approved English routes and all 18 French counterparts at 200 KiB or less. This matrix does not claim field INP, physical-device/WebPageTest evidence, complete journey coverage, manual accessibility/device review, load testing, hosted secret-history results, staging, UAT, deployment, handover or hypercare. Those remain separate ledger tasks until their named evidence exists.
