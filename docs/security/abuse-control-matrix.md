# Application abuse-control matrix

This is the application-layer evidence record for AMANOR-118. Edge WAF and bot controls add another layer but do not replace these controls.

| Threat                          | Application control                                                                                                                                                                             | Failure behavior                                                                                     | Evidence                                                                     |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Cross-site privileged mutation  | Short-lived in-memory bearer token plus exact Admin `Origin` guard on CMS, Media, Desk and account mutations; refresh/logout additionally require the session-bound cookie/header CSRF proof    | Missing, malformed and lookalike origins receive the same 403 response before domain code            | Mutation-origin and controller tests; live cross-origin Admin journeys       |
| Mongo/operator injection        | Global recursive input pipe rejects `$` keys, dotted paths, prototype keys, depth over 20 and more than 10,000 structural nodes; DTO/Zod validation constrains values                           | Generic 400 without reflecting the rejected key/value                                                | Unsafe-input and public-form adversarial tests                               |
| Stored/reflected XSS            | React escapes public/Admin rendering; generated HTML/PDF uses explicit escaping; form responses return opaque references rather than submitted content; CSP blocks inline object/base injection | User-authored markup remains plain text and is absent from response envelopes                        | Contact adversarial test, PDF escaping tests and CSP verifier                |
| Authentication enumeration      | Login failures use one external error for unknown account, password, MFA and inactive-session paths; rate keys use canonicalized bounded identifiers                                            | Uniform 401 or 429; no account-existence signal                                                      | Auth service/controller and rate-limit tests                                 |
| Spam and credential stuffing    | Mongo-backed fail-closed limits for login IP/principal, refresh, Protocol Desk, general contact, media enquiry, Press Kit and Living Dossier                                                    | 429 with bounded `Retry-After`; limiter outage returns 503 rather than admitting uncontrolled writes | Guard tests and replica-set rate-limit tests                                 |
| Cross-form denial amplification | Press Kit, media enquiries and Living Dossier use independent namespaces and limits                                                                                                             | Exhausting one workflow does not consume another workflow’s allowance                                | Public workflow guard test                                                   |
| Oversized/complex bodies        | Nest defaults are disabled; JSON is limited to 32 KiB and URL-encoded input to 16 KiB before guards/controllers; structural complexity is bounded separately                                    | Non-reflective 413 for size and 400 for complexity                                                   | Body-limit/filter tests and live Chromium/Firefox/WebKit oversized-body test |
| Sensitive error leakage         | Global error envelopes expose request ID, stable code and safe message only; body-parser and unexpected exceptions never echo bodies                                                            | 4xx/5xx response contains no submitted content                                                       | Exception-filter and E2E tests                                               |

## External launch gates

- Configure Cloudflare WAF managed rules and route-specific rate policies against the deployed origins.
- Configure Turnstile or the approved bot provider on public forms. Provider failure must route the submission to manual review instead of silently dropping or automatically rejecting a legitimate request.
- Execute credential-stuffing, distributed-IP, large-body, slow-request and bot-provider-outage drills in staging.
- Confirm alert delivery and execute the Render/Vercel deployment runbook's two-source, 31-spoof-header client-IP preservation drill through both final and direct API hostnames; retain privacy-safe status/count evidence only.
- Obtain independent security review and close every high or critical finding.
