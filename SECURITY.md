# Security policy

## Reporting a vulnerability

Use GitHub's private vulnerability reporting for this repository:

<https://github.com/stanleyHayes/ishmaeldodoo/security/advisories/new>

Do not open a public issue, discussion or pull request for a suspected security
problem. Do not include live credentials, personal data, confidential Protocol
Desk material, Room ciphertext or decrypted Room content in a report. Use only
synthetic data and the minimum evidence needed to reproduce the issue.

Include the affected revision, component, impact, reproduction steps and any
safe remediation suggestion. Maintainers will acknowledge receipt through the
private advisory, coordinate validation and remediation there, and publish an
advisory only after an appropriate fix or mitigation is available.

## Supported versions

Project AMANOR has not launched. Only the current `main` revision is supported
during development; no deployed production version is represented as supported.

## Safe-harbor boundary

Private reporting does not authorize testing production, third-party provider
accounts, real users, institutional mailboxes or confidential data. Independent
testing must use the separately authorized staging assessment scope and rules of
engagement recorded under AMANOR-123/124.
