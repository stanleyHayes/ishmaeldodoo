# Protocol Note generation

Protocol Notes are protected operational documents. They are generated by the NestJS API and are never assembled in either Next.js frontend.

## Eligibility and source data

- Only authenticated Principal or Desk Officer roles may generate a note.
- The engagement must be `accepted`, `contracted`, or `delivered`.
- A Principal or Desk Officer must save the bounded per-engagement configuration while the request is `awaiting_decision` or `held`.
- Acceptance fails closed until that configuration exists. It becomes the authoritative input for both the acceptance attachment and later protected downloads.
- Identity, biography, current title, and portrait reference resolve from the published canonical identity registry.
- The rider must be a published CMS `riderTemplate` matching the engagement type and requested locale.
- The selected portrait must be an active governed Cloudinary image with credit and licence metadata.
- Missing, unpublished, stale, malformed, oversized, or non-Cloudinary inputs fail closed.

## Included sections

- Approved biography and current title
- Approved portrait, credit, and usage licence
- CMS technical, logistics, and accessibility requirements
- Bounded per-engagement overrides
- Arrival, briefing, rehearsal, display, and lectern requirements
- Travel and accommodation arrangement
- Recording, transcript, and republication permissions from intake
- Invitation, visa, government-protocol, and form-of-address requirements
- Named host and speaker-side contacts
- Rider version and generation timestamp

Honorarium renders only for a personal-capacity request. The PDF renderer suppresses it for official capacity even if malformed persisted input contains a value.

## Repeatable print evidence

Run `npm run evidence:protocol-note` to build the production NestJS renderer and generate synthetic English personal-capacity and French official-capacity proofs under `output/pdf/`. The command uses the same `protocolNoteHtml` and headless-Chrome service as live generation, then requires Poppler to prove that each artifact is exactly one A4 page and that extracted travel/honorarium labels satisfy locale and capacity rules.

The synthetic identity, portrait and operational values are visibly marked for QA and are not production claims or approvals. For visual acceptance, render every generated page with `pdftoppm -png` and inspect the complete page for clipping, overlap, broken glyphs, list flow, section hierarchy and footer metadata.

## Remaining launch evidence

1. Publish and approve the EN/FR rider for every supported engagement type.
2. Approve the production portrait, licence, credit, and Cloudinary delivery behavior.
3. Replace the synthetic evidence with generated production EN/FR requests, compare against the approved print proof, and close accessibility/data-accuracy findings with the Principal and Desk owner.
